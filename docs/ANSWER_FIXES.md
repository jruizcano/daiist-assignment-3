## Original evidence and diagnosis

The first full dataset is preserved at `eval/answer_evaluation/e53b846b83c7dce2`. It contains 30 answers, eight blocked outputs and eleven flagged judge assessments. `before_code/` preserves the original agent, evaluator and prompts. `state.json` stores hashes of all baseline files and rejects a comparison if those files change.

The audit found several different problems:

- Real quotations linked to the wrong chunk, or a source block ID used in place of a chunk ID.
- Paraphrases, invented ellipses and incomplete table rows presented as exact quotations.
- A rounded money figure that was not the amount quoted by the source.
- A refusal containing a placeholder factual claim.
- Gross proceeds confused with proceeds after underwriting fees but before other expenses. A numerical match alone does not detect this financial distinction.
- Judge grades that confused completeness with factual support, or treated an appropriate refusal to an unanswerable question as incorrect.
- Judge quotations that combined, shortened or paraphrased source text.

These findings are engineering diagnostics, not the student's human answer grades. The unchanged baseline remains available to inspect each diagnosis.

## Targeted changes

The agent now attempts a conservative citation-link repair before validation. If a quotation does not match its cited chunk, the code searches only passages actually retrieved during that run. It changes the ID only when the exact quotation is found in one source document. Identical overlaps within that document use the first matching retrieved chunk. Cross-document ambiguity is left unresolved. It never changes the quotation or factual claim, and records every relink. Money checks and other validation still run afterward. This repairs provenance, not the semantic correctness of a claim.

The agent prompt and correction message now explicitly distinguish chunk IDs from block IDs, require whole table lines, prohibit ellipses/placeholders and self-rounded amounts, require all requested examples or a partial status, and distinguish gross proceeds from amounts after underwriting. Retrieval, embeddings and the six-call budget were not changed. The original draft and link-repair log are retained in new answer records.

The judge rubric now contains explicit examples: one supported risk when three were requested is incorrect but supported; an appropriate refusal of an unanswerable question is correct and supported. Empty evidence lists are permitted for pure refusals. It asks for short exact quotations and warns against importing metadata headings into source quotations. The judge still uses the same low-cost model, with reasoning effort changed from low to medium and an 8,192-token output cap. Prompt and reasoning settings changed together, so their separate contributions cannot be inferred from this experiment. Raw responses and usage are cached.

The checks were not weakened to accept paraphrases or invented evidence. Remaining validation failures stay visible and excluded from valid-grade metrics.

## Three separate comparisons

1. **Offline citation replay:** apply only deterministic relinking to the old blocked drafts. This uses no API calls and holds the draft, claims and retrieved text fixed. Passing after a relink proves only that the local checks passed.
2. **Judge-only stage:** copy the original 30 saved answer files byte-for-byte into a new evaluation dataset and rejudge eligible outputs. The comparison verifies identical hashes. Original guardrail blocks stay blocked. Changes in this stage reflect the revised judging procedure and model variability, not improved answers. Reused answer costs describe the original runs and are not newly incurred costs.
3. **Updated-system stage:** run the revised agent on all 30 questions, then apply the revised judge. No previously successful answers are selectively kept. Retrieval uses the same implementation and index, but the model can choose different searches, and generation is stochastic. This is a full-system development comparison, not an isolated causal test or held-out benchmark.

The judge-only dataset records the original answer-generation code hashes, its source dataset identifier and each reused answer's hash. The updated dataset records the revised code. `latest.json` points to the updated dataset after both stages complete. Rerunning unchanged code reuses both stages. The original baseline files are never rewritten by the comparison.

## Reading results and continuing

Fewer flags does not imply higher accuracy. Read answer status, judge validity, correctness and support separately; review any regressions as well as improvements. Overall accuracy remains unavailable when judge grades are missing or invalid. Even fully validated judge grades are provisional model assessments. Same-model bias and reuse of this test set during development remain limitations.

Once a complete updated run is selected, freeze it and use that dataset's `human_review.html` to independently grade at least 20 answers before viewing individual judge grades. Import that export using the commands in ANSWER_EVALUATION.md. Old passage reviews and these diagnostics are not substitutes. Judge-only and updated-answer datasets have different IDs, so human grades cannot silently transfer between them.
